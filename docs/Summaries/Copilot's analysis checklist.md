## API count and why it is justified

The brief’s 6–10 meaningful HTTP operations is an indicative guide, not a hard cap, and it cautions against splitting coherent work into trivial endpoints. A raw count across this project can look high because it combines customer-facing routes, staff-facing routes, internal service-to-service routes, and infrastructure routes such as health checks. Those routes support distinct customer and staff workflows or preserve the services’ separate data ownership: staff accesses customer-owned order data through the customer service rather than querying its database directly. The count should therefore be explained as a deliberate consequence of the two-client, two-service design—not as extra operations added to inflate scope.
